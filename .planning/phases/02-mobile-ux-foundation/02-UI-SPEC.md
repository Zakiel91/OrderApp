## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, chip internal padding |
| sm | 8px | Compact element spacing, gap between Back/Next buttons |
| md | 16px | Default section padding (`p-4`) |
| lg | 24px | Section spacing (`space-y-6`) |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing (e.g. `pb-28` ≈ 112px bottom clearance for BottomNav) |

Exceptions:
- Touch target minimum: **48px height** (UX-03). Applied via `min-h-[48px]` + padding. Visual size of icons/labels is unchanged.
- BottomNav wizard buttons: **52px height** — matches existing `buttonClass` (`min-h-[52px]`) and existing BottomNav tab buttons (`min-h-[52px]`). Source: CONTEXT.md D-09, FormField.tsx.
- Stone result list items: upgrade from `min-h-[44px]` to `min-h-[48px]`. Source: CONTEXT.md D-08.
- Bottom content clearance: `pb-28` (112px) on wizard pages — unchanged after BottomNav wizard mode because button row height is the same.

## Component Inventory

Components touched by this phase. No new components are created.

### BottomNav — Wizard Mode (new behavior, existing component)

**Standard mode** (current, unchanged):
- 4 tab buttons: Orders, New Order, Fix Order, Settings
- Fixed bottom, `bg-[var(--color-surface)]`, border-top `--color-border`, `z-50`, `safe-area-bottom`
- Each tab: `min-h-[52px]`, emoji icon + 11px label, flex-col centered

**Wizard mode** (new, triggered when `pathname === '/orders/new'` or `pathname === '/orders/fix'`):
- Replaces the 4 tabs with 2 buttons filling the full width
- Left button: Back — uses `secondaryButtonClass` (`bg-surface`, `min-h-[50px]`, border, `text-[15px] font-medium`)
- Right button: Next (mid-steps) or Submit (last step) — uses `buttonClass` (`bg-primary`, `min-h-[52px]`, white text, `text-[15px] font-semibold`)
- On Step 1 of New Order wizard: only the Next button shown (no Back on first step — matches existing page behavior)
- On last step: right button label changes to "Submit" with primary style; left button remains Back
- Layout: `flex` with `gap-2 px-4 py-2`, maintaining same overall height as standard mode

Source: CONTEXT.md D-01, D-02, D-03; `specifics` block (Back left / Submit right, primary style).

### Scroll Reset (UX-01)

Not a component change — a behavior contract.

- Both `NewOrderPage.tsx` and `FixOrderPage.tsx` add `useEffect(() => { window.scrollTo(0, 0) }, [step])`
- No animation (`behavior: 'smooth'` is explicitly forbidden — D-05)
- Fires on every step change including forward and backward navigation

## Interaction Contracts

### Wizard Step Navigation

| State | Back button | Next/Submit button |
|-------|-------------|-------------------|
| Step 1 of N | Hidden | "Next" — primary style |
| Step 2..N-1 of N | "Back" — secondary style | "Next" — primary style |
| Last step (N of N) | "Back" — secondary style | "Submit" — primary style |
| Submit in progress | "Back" — disabled (opacity-40) | "Submit" — disabled (opacity-40) |

Source: CONTEXT.md D-01, D-02; `specifics` block; `buttonClass` includes `disabled:opacity-40 disabled:cursor-not-allowed`.

### Touch Target Contract

All interactive controls in the wizard must satisfy:
- Minimum rendered touch target height: **48px**
- Achieved via `min-h-[48px]` Tailwind class (or equivalent padding that produces 48px box height)
- Visual label/icon size: unchanged
- No 44px exceptions — 48px is the floor for this phase (UX-03 specification)

Source: CONTEXT.md D-07, D-08, D-09; REQUIREMENTS.md UX-03.

## Constraints and Non-Negotiables

- No new components — only modifications to `BottomNav.tsx`, `NewOrderPage.tsx`, `FixOrderPage.tsx`, `Step2Client.tsx`, `Step4Stones.tsx`, and their associated contexts.

- How BottomNav accesses context state (submit handler, step, setStep) is left to planner discretion — this contract does not specify the wiring pattern.
- Brownfield constraint: all changes are additive. No full rewrites of existing components.
