## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline spacing (e.g. `ms-1`) |
| sm | 8px | Compact element spacing (e.g. `mb-1.5`, `gap-2`) |
| md | 16px | Default element spacing (e.g. `px-4`, `mb-5`) |
| lg | 24px | Section padding (e.g. `pt-3 pb-2`) |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions:
- Toast top offset: `top-4` (16px) — keeps toast clear of status bar
- BottomNav bottom padding: `pb-28` (112px) — reserved scroll clearance on page wrapper
- Touch target minimum: 48px height on all interactive elements (established in Phase 2)
- BottomNav buttons: `min-h-[52px]` — slightly above minimum for primary CTA prominence

Source: existing Tailwind classes observed in `BottomNav.tsx`, `NewOrderPage.tsx`, `FormField.tsx`.

## Typography

Declared weights: 2 maximum — `400 (regular)` and `700 (bold)`.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 17px | 400 (regular) | 1.5 |
| Label | 15px | 400 (regular) | 1.4 |
| Caption / muted | 11–14px | 400 (regular) | 1.4 |
| Heading (h1) | 28px (1.75rem) | 700 (bold) | 1.2 |

Notes:
- Body 17px is the declared `font-size` on `body` in `src/index.css` — do not deviate
- Label 15px is the established `text-[15px]` in `FormField.tsx` and button classes
- Toast chip text: 14px, weight 400 (regular) — small enough to be unobtrusive, legible at a glance
- Step indicator text in `ProgressBar.tsx`: `text-sm` (14px), `text-[var(--color-text-muted)]`
- No `font-weight-medium` (500) — any element previously specified as 500 uses 400 instead

Source: `src/index.css` body declaration, `src/components/FormField.tsx` class constants.

## Color

All values from `src/index.css` CSS custom properties.

| Role | Token | Hex | Usage |
|------|-------|-----|-------|
| Dominant (60%) | `--color-bg` | `#f4f6fa` | Page background, outer surfaces |

Accent (`#b8934a`) reserved for:
- Active tab indicator in BottomNav
- ProgressBar gradient fill (right end)
- Required field asterisk in FormField
- Input focus ring (`focus:ring-[var(--color-accent)]/20`)
- Accent emphasis text (sparingly)

**NOT** for: toast chip, step transition overlay, or any new Phase 3 element.

DraftSavedToast color contract:
- Background: `var(--color-success)` (`#16a34a`) — green chip
- Text: white (`#ffffff`)
- No border, no shadow, no close button
- Opacity on entry: animates from 0 to 1; on exit: fades to 0

Source: `src/index.css`, `src/components/BottomNav.tsx`, `src/components/FormField.tsx`, `03-CONTEXT.md` D-03.

## Interaction Contracts

### DraftSavedToast (UX-04)

| Property | Value |
|----------|-------|
| Position | `fixed top-4 left-1/2 -translate-x-1/2` — floating, above content |
| Z-index | `z-40` — below BottomNav (`z-50`), above page content |
| Trigger | Any `form` state change detected via context hook |
| Debounce | 500ms of inactivity after last form change |
| Visible duration | 2 seconds after appearing |
| Enter animation | Fade in — opacity 0 → 1, duration 150ms |
| Exit animation | Fade out — opacity 1 → 0, duration 200ms |
| Content | `✓ {t('draft_saved')}` — checkmark prefix + translated text |
| RTL compatibility | `left-1/2 -translate-x-1/2` centering works in both LTR and RTL |
| Implementation | `useEffect` + `setTimeout` + cleanup — no external library |

Source: `03-CONTEXT.md` D-03 through D-08, code_context section.

### Step Transition (UX-05)

| Property | Value |
|----------|-------|
| Duration | 200ms |
| Style | Fade + slide: advancing (Next) slides left; going back (Back) slides right |
| Enter | New step fades in + slides in from edge (direction-aware) |
| Exit | Old step fades out + slides out to opposite edge |
| Implementation | Tailwind CSS keyframes or inline `@keyframes` in CSS — no Framer Motion |
| Scroll reset interaction | `window.scrollTo(0, 0)` fires after transition starts (does not block animation) |
| Layout impact | Transition wrapper must not alter page layout — use `overflow-hidden` on wrapper if needed |

Source: `03-CONTEXT.md` D-09 through D-12.

### Step Indicator / ProgressBar (UX-02)

| Property | Value |
|----------|-------|
| Status | Already implemented — no visual change required |
| Placement | Top of page, above step content, below page header |
| Text format | `{t('step')} {current} {t('of')} {total}` |
| Bar style | Gradient fill: `linear-gradient(90deg, var(--color-primary), var(--color-accent))` |
| Transition | `transition-all duration-300` on bar fill width |

Source: `src/components/ProgressBar.tsx` (verified — fully satisfies UX-02), `03-CONTEXT.md` D-01, D-02.

## Constraints Summary

These constraints apply to ALL Phase 3 implementation:

1. No new animation library — Tailwind CSS keyframes or `@keyframes` in `src/index.css` only
2. No hard validation blocking — out of scope (established project constraint)
3. RTL compatibility required — all fixed positioning must use centering patterns, not `left`/`right` offset
4. No emoji in toast — use Unicode `✓` (U+2713) for the checkmark
5. Translation keys always — never hardcode text strings in components
6. Stale worker copy — never touch `C:\OrderApp\Dashboard\worker\`; canonical worker is `C:\Dashboard\worker\`
7. Additive only — no breaking rewrites of existing components
