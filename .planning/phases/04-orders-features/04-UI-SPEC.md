## Spacing Scale

Declared values (multiples of 4 only). All existing Tailwind utility classes follow this scale.

| Token | Value | Tailwind | Usage |
|-------|-------|----------|-------|
| xs | 4px | gap-1, p-1 | Icon gaps, badge padding |
| sm | 8px | gap-2, p-2 | Inline elements, badge pill px |
| md | 16px | p-4, gap-4 | Card inner padding, section spacing |
| lg | 24px | p-6, gap-6 | Page section breaks |
| xl | 32px | mb-8 | Major layout gaps |
| 2xl | 48px | pb-12, min-h-[48px] | Bottom nav clearance zone |
| 3xl | 64px | pb-16 (pb-24 = 96px) | Page bottom padding (accounts for fixed nav) |

Exceptions:
- Page bottom padding: `pb-24` (96px) — established Phase 2 to clear fixed BottomNav; all pages use this.
- Minimum touch target: `min-h-[48px]` on all interactive elements (Phase 2 contract UX-03). Inputs use `min-h-[50px]` from inputClass. Primary button uses `min-h-[52px]` from buttonClass.
- Search input row + status dropdown row: minimum `min-h-[48px]` each (touch target requirement).
- Order count label: `text-xs` inline element — not a touch target, no minimum height required.

## Feature Contracts

### FEAT-01 — EditOrderPage

**Route:** `/orders/:id/edit`

**Availability:** Only rendered when `order.status === 'new'`. Edit button in OrderDetailPage top action row is conditional on this status.

**Page structure (top to bottom):**
1. Top action row: order number as plain `<h1 className="text-lg font-bold">`, then `Save Changes` button (`buttonClass` width `w-auto px-4`), then `Cancel` button (`secondaryButtonClass` width `w-auto px-4`). Row: `flex gap-2 mb-4 items-center`.
2. Form fields in a single scrollable `<div className="space-y-0">` wrapped in a `bg-[var(--color-surface)] rounded-xl p-4 mb-4` card — no multi-section grouping needed for mobile flat form.
3. Page uses `p-4 pb-24` outer wrapper (matches all other pages).

**Field order in flat form:**

| Field | Input Type | i18n key (existing) | Notes |
|-------|-----------|---------------------|-------|
| client_name_raw | text input | `client_name` | plain text, no lookup |
| client_phone | tel input | `client_phone` | |
| client_email | email input | `client_email` | |
| jewelry_type | select | `jewelry_type` | reuse same options as Step3 |
| metal | text input | `metal` | free text (not constrained select) |
| size | text input | `size` | |
| description | textarea (3 rows) | `fix_description` or new key `description` | |
| main_stone_parcel | text input | `main_stone` | plain text, no inventory search |
| price_to_client | number input | `price_to_client` | prefix `$` via wrapper |
| deadline | date input | `deadline` | |
| comment | textarea (3 rows) | `fix_comment` → new key `comment` | |

All inputs use `inputClass`. All textareas use `inputClass` + explicit `rows={3}`. All wrapped in `<FormField label={t('...')} >`.

**Save action:**
- Calls `updateOrder({ id, ...formData })`
- On success: `navigate(\`/orders/${id}\`)`
- On error: show inline error banner below action row — `bg-red-500/10 text-red-400 border border-red-500/30 rounded-xl p-3 mb-4 text-sm`
- Save button shows `disabled` + text `...` while saving (`buttonClass` has `disabled:opacity-40`)

**Cancel action:** `navigate(\`/orders/${id}\`)` — no confirmation, no destructive action.

**Touch targets:** All inputs `min-h-[50px]` (from inputClass). Save/Cancel buttons `min-h-[50px]` (from secondaryButtonClass/buttonClass). FormField label area is non-interactive, no touch target requirement.

**Edit button in OrderDetailPage:**
- Placement: top action row alongside Back and Delete buttons — `flex gap-2 mb-4`
- Conditional: only rendered when `order.status === 'new'`
- Style: `secondaryButtonClass` with `w-auto px-4` (not full-width)
- Label: `t('edit')` — new i18n key

### FEAT-02 — Search/Filter Bar in MyOrdersPage

**Placement:** Below header row, above order list. Separate `div` block.

**Layout:**
```
[header row: "My Orders" h1 + count label + salesman badge]
[search input | status select]  ← flex row, gap-2, mb-4
[order list]
```

**Search input:**
- Class: `inputClass` (full width or `flex-1`)
- Type: `text`
- Placeholder: `t('search_orders')` — new i18n key (en: "Search orders...", ru: "Поиск заказов...", he: "חיפוש הזמנות...")
- Behavior: filters `orders` array client-side by `order_number` (case-insensitive contains) OR `client_name_raw`/`client_name` (case-insensitive contains). No debounce needed for 200 items.

**Status filter select:**
- Class: `selectClass` with explicit `w-auto` or fixed width `w-[140px]` to avoid taking full row width
- First option: `t('all_statuses')` — new i18n key (en: "All statuses", ru: "Все статусы", he: "כל הסטטוסים")
- Subsequent options: keys from `STATUS_COLORS` record — use existing status string as value and label (translated status display is deferred; use raw status string for now matching existing badge behavior)

**Order count display:**
- Position: same flex row as `<h1>` and salesman badge — right-aligned, between h1 and salesman badge
- Format when no filter active: `t('orders_count', { count: total })` — new i18n key pattern
  - en: `"{count} orders"`, ru: `"{count} заказов"`, he: `"{count} הזמנות"`
- Format when filter active: `t('orders_filtered', { filtered: filteredCount, total })` — new i18n key
  - en: `"{filtered} of {total}"`, ru: `"{filtered} из {total}"`, he: `"{filtered} מתוך {total}"`
- Style: `text-xs text-[var(--color-text-muted)]`
- `total` comes from `getOrders(1, 200)` response `res.total` (already returned by API, currently unused)

**Filter logic:**
- `filteredOrders` = orders filtered by both search text AND status (both must match when both are active)
- Display `filteredOrders` instead of `orders` in the list
- Count is "filtered" mode whenever search text is non-empty OR status select is not "all"

### FEAT-03 — Error State in MyOrdersPage

**Trigger:** `getOrders` throws — replace `catch(() => {})` with `catch(e => setError(e.message))`.

**State:** `const [error, setError] = useState<string | null>(null)` — same pattern as OrderDetailPage.

**Error card replaces order list area only** — header, search bar, and salesman badge remain visible above.

**Layout (error card):**
```
<div className="flex flex-col items-center justify-center min-h-[60vh] p-6">
  <p className="text-[var(--color-text-muted)] text-center mb-4">{t('orders_load_error')}</p>
  <button className={secondaryButtonClass + ' w-auto px-6'} onClick={handleRetry}>
    {t('retry')}
  </button>
</div>
```

**Retry button:** calls `handleRetry` which re-runs `getOrders(1, 200)` — resets `error` to `null` and `loading` to `true` first.

**No emoji or icon** in the error card — plain text only, matching existing OrderDetailPage error pattern exactly.

## Accessibility

- All inputs have associated `<label>` via `FormField` wrapper — no bare inputs.
- Search input: `aria-label={t('search_orders')}` if no visible label above it.
- Status select: `aria-label={t('all_statuses')}` or explicit `<label>` hidden with `sr-only` if design is label-free.
- Error card: error text is in a `<p>` element, not a `<div>` — assistive tech reads it as paragraph.
- RTL: all new components use `ms-*`/`me-*` Tailwind utilities, not `ml-*`/`mr-*`. Inputs inherit `[dir="rtl"]` from `index.css`.
- Touch targets: all interactive elements `min-h-[48px]`. Search input and status select are in the same flex row — each must independently meet `min-h-[48px]`.
